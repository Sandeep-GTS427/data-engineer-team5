# Data Profiling – Test Results

## 1. Overview

This document describes the testing performed on the CSV Data Profiling module developed as part of Team 5's Data Engineering work.

The profiling module is implemented in `src/data_profiler.py` using Python's built-in `csv` module.

The purpose of profiling is to understand the structure and quality of a dataset by generating dataset-level and column-level statistics.

## 2. Profiling Features

The profiler currently supports the following features:

- Total row count.
- Total column count.
- Column name identification.
- Automatic data type detection.
- Missing value count.
- Missing value percentage.
- Distinct value count.
- Minimum and maximum values for supported numeric and date/time columns.

### Supported Data Types

| Data Type | Description |
|---|---|
| Integer | Whole numbers |
| Decimal | Decimal and numeric values |
| String | Text values |
| Boolean | True/False values |
| Date | Date values |
| Timestamp | Date and time values |
| Mixed | Column containing incompatible data types |
| Unknown | Column containing only missing values |

## 4. Test Scenarios

### Test Case 1: Different Data Types

**Dataset:** `profiling_mixed_types.csv`

Purpose: Verify automatic detection of different column data types.

| Column | Expected Type | Actual Type | Result |
|---|---|---|---|
| customer_id | integer | integer | PASS |
| name | string | string | PASS |
| age | integer | integer | PASS |
| salary | decimal | decimal | PASS |
| is_active | boolean | boolean | PASS |
| joining_date | date | date | PASS |
| last_login | timestamp | timestamp | PASS |

Dataset dimensions:
- Rows: 4
- Columns: 7

**Result:** All seven column data types were detected correctly.

### Test Case 2: Missing Value Profiling

**Dataset:** `profiling_missing_values.csv`

Purpose: Verify missing value detection and null percentage calculation.

| Column | Null Count | Null Percentage |
|---|---:|---:|
| customer_id | 0 | 0% |
| name | 1 | 25% |
| age | 1 | 25% |
| salary | 1 | 25% |
| is_active | 1 | 25% |

**Result:** Missing values and their percentages were calculated correctly.

### Test Case 3: Mixed Data Type Detection

**Dataset:** `profiling_mixed_data.csv`

Purpose: Identify columns containing incompatible data types.

| Column | Values | Detected Type |
|---|---|---|
| customer_id | 1, 2, 3, 4 | integer |
| age | 25, 30, unknown, 35 | mixed |

**Result:** The profiler correctly identified the age column as mixed.

### Test Case 4: Distinct Value Profiling

**Dataset:** `profiling_duplicates.csv`

Purpose: Verify the distinct value count for columns containing repeated values.

| Column | Total Records | Distinct Count |
|---|---:|---:|
| customer_id | 5 | 5 |
| city | 5 | 3 |

**Result:** The profiler correctly calculated unique values and excluded repeated values from the distinct count.

Note: Distinct value profiling is different from duplicate-row detection.

## 7. Observations

1. The profiler successfully identifies supported data types.
2. Missing values are excluded from distinct counts.
3. Null percentages are calculated using the total number of dataset rows.
4. Mixed data types are identified as `mixed`.
5. Minimum and maximum values are calculated for supported numeric and date/time columns.
6. String and Boolean columns currently return null for minimum and maximum values.
7. Profiling is currently implemented as a standalone module and has not yet been integrated into the FastAPI response.

## 8. Current Limitations

- CSV data is currently loaded into memory during profiling.
- Mean, median and standard deviation are not implemented.
- Top-N values and histograms are not implemented.
- Profiling output format is provisional and requires confirmation against the Team 1 and Team 2 API contract.
- Large dataset performance and memory usage require further testing.

## 9. Conclusion

The standalone CSV Data Profiling module has successfully completed the initial manual profiling scenarios and automated regression testing.

The profiler correctly handles different data types, missing values, mixed-type columns and distinct value calculations.

All 33 existing automated unit tests passed after the profiling implementation and additional manual testing.

Further integration work will proceed after confirmation of the common repository structure and API contract from the relevant teams.
