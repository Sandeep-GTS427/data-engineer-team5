## 1. Purpose

Document the interface mapping between Team 5's existing dataset validation and profiling implementation and Team 1's preprocessing service.

This document identifies available fields, missing fields, integration requirements and pending confirmations.

## 4. Current Team 5 Capabilities

- CSV dataset validation.
- Missing-value detection.
- Duplicate-row detection.
- Expected data type validation.
- Dataset profiling and column statistics.
- PostgreSQL dataset metadata lookup.
- FastAPI dataset validation endpoint.
- Automated regression tests.

The standalone profiler is not yet integrated into the FastAPI endpoint.

## 5. Identified Integration Gaps

1. Agree on the dataset reference and file-location handoff.
2. Define the profiling metadata required by Team 1.
3. Confirm ownership of target and problem-type information.
4. Confirm preprocessing responsibility and transformation boundaries.
5. Obtain Team 1's Python implementation or API access.
6. Align validation warnings and errors with the agreed response contract.
7. Confirm whether Team 1 requires CSV, XLSX or DataFrame input for the initial integration.

## 6. Pending Confirmations

## 7. Proposed Integration Workflow

CSV/XLSX Dataset → Dataset Validation → Dataset Profiling → Agreed Data Handoff → Team 1 Preprocessing → Processed Dataset Output.

This workflow is proposed for coordination and requires confirmation from the relevant teams.

## 8. Conclusion

Team 5 has implemented initial dataset validation, profiling and PostgreSQL metadata lookup capabilities.

Team 1 has shared its preprocessing request and response interface descriptions. Actual integration remains pending access to the preprocessing implementation and confirmation of the dataset handoff contract.

No changes to the existing API or validation implementation are proposed until the integration requirements are confirmed.
